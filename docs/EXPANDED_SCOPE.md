# ฟังก์ชัน RM ที่เพิ่มและการเชื่อมต้นแบบล่าสุด

อัปเดต 18 ตุลาคม 2569 — ต่อยอด React + Express + SQLite เดิม ไม่แทนที่โปรเจกต์ด้วย HTML สาธิต ใช้ธีมเขียวเดิมและข้อมูลจริงในฐานข้อมูล ยอดเริ่มต้นเป็นศูนย์จนมีรายงาน

## หน้าจอและพฤติกรรม

| หน้า / เส้นทาง hash | การทำงาน |
|---|---|
| `#import` | ช่องข้อความเดียว แนบไฟล์ได้ เลือกฝากไว้ค้นหาเท่านั้นได้; แบบฝากไม่สร้างกิจกรรมหรือนับยอด |
| `#activity/:id` | เปรียบเทียบต้นฉบับกับข้อมูลที่เสนอ เพิ่มตัวเลขพร้อมหน่วย เพิ่มหน่วยงานร่วม แก้ตามสิทธิ์ แล้วจึงยืนยันพร้อมสรุป |
| `#dashboard/mine` | ผลของผู้รายงานเองและรายการต้นทาง |

| `#projects` | ลงทะเบียนโครงการที่หน่วยงานมีอยู่ เชื่อมรายงานจริง เปรียบเทียบตัวชี้วัดที่มีเป้าหมายยืนยันแล้ว ไม่คำนวณเปอร์เซ็นต์จากจำนวนรายงานเฉย ๆ |
| `#calendar` | ปฏิทินวันที่กิจกรรมจากรายงาน กรองหน่วยงานและของฉัน คลิกวัน/รายงานได้ ไม่ใช่ปฏิทินนัดหมายหรือคำสั่งงาน |
| `#reports` | สร้างและเปิดฉบับย้อนหลัง รายเดือน/ไตรมาส/ปี ส่งออก DOCX หรือพิมพ์ HTML เป็น PDF; เปิดดูร่างคำบรรยายที่โมเดลเสนอและตรวจเทียบ snapshot |
| `#quality` | ตรวจคู่ที่อาจซ้ำ ยืนยันรวม/คืนรายการ รักษาหลักฐานเดิม; หัวหน้าปิดและเปิดรอบ; อ่านไฟล์ฝากเพื่อทำดัชนีค้นหา |
| `#amendments` | เจ้าของขอแก้ไขหลังปิดรอบ หัวหน้าหน่วยอนุมัติหรือไม่อนุมัติพร้อมเหตุผล |
| `#inbox` | ข้อความ LINE ที่ได้รับจริง เลือกข้อความและรูปของกิจกรรมเดียวกันเป็นชุด ดาวน์โหลดหลักฐานและเสนอข้อมูล |
| `#line-link` | สร้างรหัสใช้ครั้งเดียวเพื่อผูกบัญชี LINE ส่วนตัวกับบัญชี RM ที่เข้าสู่ระบบแล้ว |
| `#news-candidates` | ประชาสัมพันธ์ดูรายงานที่เจ้าหน้าที่เสนอ หรือเรียกโมเดลช่วยคัดรายงานพร้อมสรุป |
| `#news` / `#feed` | ประชาสัมพันธ์จัดร่าง เลือกรูป ยืนยันข่าว; ผู้ใช้ภายในอ่านข่าว กดถูกใจ แสดงความคิดเห็นและคัดลอกลิงก์ `#feed/:id` |
| `#report-settings` | ผู้ดูแลกำหนดชื่อ/คำเรียกตัวเลข หน่วย วิธีรวม หน่วยงานที่ใช้แม่แบบ ปีงบประมาณ การสร้างฉบับตามรอบและการตอบรับ LINE |

## สิทธิ์และการนับ

- ผู้ใช้ภายในอ่านข้อมูลข้ามหน่วยได้ตามขอบเขตเดิม เจ้าหน้าที่แก้รายงานของตน หัวหน้าแก้เฉพาะหน่วยใน scopes การเป็นผู้บริหาร/ประชาสัมพันธ์/แอดมินอย่างเดียวไม่ให้สิทธิ์แก้รายงานของผู้อื่น
- รอยืนยันหมายถึงยังไม่ได้ตรวจข้อมูลให้พร้อมสรุป ไม่ใช่ต้องให้หัวหน้าอนุมัติทุกรายการ เจ้าของที่มีสิทธิ์ยืนยันได้
- หน่วยงานร่วมเก็บเป็นรายชื่อในรายงานเดิม ไม่คัดลอกกิจกรรมไปทุกฝ่ายเพื่อเพิ่มยอด การค้นหาครอบคลุมรายชื่อผู้ร่วม
- นับเฉพาะ ready ที่ไม่ถูกระบุว่าซ้ำ ข้อความและรูปหลายชิ้นอาจเป็นกิจกรรมเดียวกัน ต้องตรวจการจัดชุด
- คน / ราย / ครั้งบริการ / จำนวนกิจกรรม / ตัน แยกกัน จำนวนผู้เข้าร่วมสะสมไม่เท่ากับจำนวนบุคคลไม่ซ้ำ ระบุหน่วยอื่นได้ เช่น ชุด หรือ บาท โดยยอดต่างหน่วยแสดงแยกกัน ตัวเลขงบประมาณต้องมาจากเอกสารที่ตรวจแล้ว ไม่ใช่ระบบบัญชีเต็มรูปแบบ
- แม่แบบกำหนด sum, max หรือ latest ตามนิยามตัวเลข แปลงกิโลกรัมกับตันได้เฉพาะตัวเลขที่ตรงแม่แบบ ไม่รวมหน่วยหรือชื่อที่ไม่รองรับเข้าด้วยกัน
- ยืนยันรายการซ้ำต้องมีสิทธิ์แก้ทั้งสองรายการและตรวจหลักฐานก่อน คืนรายการได้ และรายงานเดิมยังเปิดดูได้
- เมื่ออนุมัติคำขอแก้หลังปิดรอบ ระบบเปิดรอบที่ทับซ้อนวันที่นั้น **ทั้งหน่วยงาน** ไม่ใช่เฉพาะรายงานเดียว หน้าพิจารณาแจ้งผลนี้ชัดเจน หัวหน้าต้องปิดรอบอีกครั้งเมื่อแก้ครบ
- Snapshot สรุปและร่างคำบรรยายที่ยืนยันแล้วไม่แก้ทับตามต้นฉบับที่เปลี่ยนภายหลัง ต้องสร้างฉบับใหม่
- ความคิดเห็นเป็นข้อความธรรมดา React escape ให้ ผู้เขียนลบของตนได้ ประชาสัมพันธ์ลบเพื่อดูแลฟีดได้ มี audit การลบ ข่าวที่ยังไม่เผยแพร่ไม่มีช่องสนทนาสำหรับผู้ชม

## ขอบเขตที่เลือกจาก HTML ของเพื่อน

นำฟอร์มตัวเลขยืดหยุ่น ชิปหน่วยงานร่วม ไทม์ไลน์ที่ย้อนดู/แก้ได้ ฟีดแบบโพสต์ และสถานะระบบมาเชื่อมข้อมูลจริงแล้ว หมวดใหม่ใช้กลไกเพิ่มประเภทงานเดิมที่ตรวจชื่อซ้ำ ส่วนแม่แบบสรุปให้ผู้ดูแลยืนยัน เพื่อไม่ให้สะกดต่างกันแล้วรวมยอดผิด

ยังคงข้อสรุปก่อนหน้า: ไม่มีส่วนวางแผน/มอบหมายงาน เตือนงานค้างทุกวัน ยกระดับหลังสามวัน หรือประเมิน KPI บุคลากร ไม่มี Facebook API ไม่มีการนับคนจากภาพถ่าย ไม่สร้างบัญชีที่มีสิทธิ์พิเศษโดยให้ผู้ใช้เลือกเองใน LINE และไม่ปิดบัญชีเพียงเพราะ unfollow บอต

ปฏิทินเป็นวันที่กิจกรรมจากรายงานจริง ไม่อ้างว่าสกัดนัดหมาย/ตรวจเวลาชนกันแล้ว ปุ่มใน HTML ที่เพียงแสดง toast ไม่ถูกนำมาอ้างว่าเชื่อม LINE หรือส่งออกสำเร็จ

## เริ่มใช้งาน

ใช้ Node ตาม `package.json` (24.13 ขึ้นไป) และทำตามขั้นตอนบัญชีผู้ดูแลใน README เดิม

```sh
npm ci
cp .env.example .env
npm run admin:create
npm run dev
```

ถ้ามี `.env` และบัญชีแล้วไม่ต้องสร้างทับ ให้เพิ่มเฉพาะค่าที่ขาด ก่อนใช้กับข้อมูลจริงให้สำรองฐานข้อมูลและโฟลเดอร์ uploads ด้วย `npm run backup` ตามคู่มือเดิม เมื่อเปิด API ระบบรัน migration 7–9 แบบเพิ่มตาราง/คอลัมน์ ไม่ล้างรายงานเดิม หากต้องย้อนโค้ดควรใช้ backup ที่สอดคล้องกับ schema

### ตัวอ่านเอกสาร

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r scripts/requirements-ai.txt
```

กำหนด `DOCUMENT_PYTHON` เป็น absolute path ไปยัง Python ใน `.venv` (Windows ใช้ `Scripts/python.exe`) PDF ที่เป็นข้อความ, XLSX/XLS, DOCX และ TXT จะอ่านข้อความก่อน ไม่จำเป็นต้อง OCR ทุกไฟล์ สูตร Excel ใช้ค่าที่ cache ในไฟล์; เซลล์ที่ไม่มีค่าจะไม่ถูกคำนวณใหม่

รูปและ PDF สแกนต้องติดตั้ง EasyOCR เพิ่มใน environment เดียวกันและเตรียมน้ำหนักโมเดล Thai/English ให้ผู้ใช้ระบบปฏิบัติการที่รันเซิร์ฟเวอร์ ตัวอ่านตั้ง `download_enabled=False` จึงไม่ดาวน์โหลดโมเดลแอบระหว่างรับรายงาน OCR อ่านตัวอักษรเท่านั้น ไม่ยืนยันความถูกต้องของข้อเท็จจริง

ข้อจำกัดต่อครั้ง: PDF 20 หน้าแรก, Excel 5,000 แถวต่อชีต, ข้อความ 100,000 อักขระ และเวลาตัวอ่าน 90 วินาที มีคำเตือนเมื่ออ่านไม่ครบหรือ dependency ไม่พร้อม ผู้ใช้แบ่งไฟล์/ตรวจต้นฉบับและกรอกข้อมูลที่ขาดได้

### โมเดลท้องถิ่น (ไม่ใช้ Gemini / ไม่บังคับ fine-tune)

ตั้งค่า Ollama ที่รองรับ `/api/chat` และ structured JSON แล้วกำหนด:

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=ชื่อโมเดลภาษาไทยที่ติดตั้งและทดสอบบนเครื่องแล้ว
```

โปรเจกต์ไม่ดาวน์โหลดน้ำหนักโมเดลหรือส่งข้อมูลไปคลาวด์ให้อัตโนมัติ เมื่อเว้น `OLLAMA_MODEL` ระบบใช้กฎค้นวันที่/ตัวเลขแบบจำกัดและติดป้าย `rules` ไม่แสดงว่าใช้ AI แล้ว ส่วนคัดข่าวและร่างเอกสารจะบอกว่ายังไม่ได้ตั้งค่าโมเดล

มีจุดใช้โมเดลสามจุด:

1. เสนอข้อมูลจากข้อความและเอกสารที่อ่านแล้ว แยกหลายกิจกรรมได้ ผู้ใช้เลือกนำแต่ละรายการมาใช้เป็นร่าง ไม่ยืนยันพร้อมสรุปเอง
2. เสนอรายงานที่อาจเหมาะให้ประชาสัมพันธ์พิจารณา ผลเป็นเหตุผลและข้อความอ้างอิง ไม่เผยแพร่ข่าวเอง
3. ร่างคำบรรยายสรุปจาก snapshot ที่คำนวณแล้ว แต่ละหัวข้ออ้างรหัสกิจกรรม ผู้สร้างร่างตรวจ/แก้ข้อความและยืนยันก่อนดาวน์โหลดฉบับใช้งานเป็น Word หรือพิมพ์ PDF

ระบบตรวจ schema และรหัส/ข้อความอ้างอิง แต่นี่ไม่ใช่การรับรองว่าเนื้อหาจากโมเดลถูกต้องทุกคำ ต้องทดลองกับรายงานจริงและประเมินความแม่นยำก่อนใช้งานจริง ร่างสรุปจำกัด 200 กิจกรรมและข้อความต้นทาง 100,000 อักขระเพื่อให้แบ่งการประมวลผลได้ชัดเจน

### LINE

ใช้บัญชี OA และ webhook ที่ตรวจลายเซ็นกับกลุ่มที่ได้รับอนุญาตตามคู่มือเดิม กำหนดค่าฝั่งเซิร์ฟเวอร์ `LINE_CHANNEL_SECRET`, `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_REPORT_GROUP_ID`; ส่งข่าวใช้ `LINE_NEWS_GROUP_ID` ตามการกดส่งของประชาสัมพันธ์

- ผู้ใช้ที่มีบัญชี RM เข้าหน้าผูก LINE สร้างรหัสอายุ 10 นาที แล้วส่งข้อความรหัสในแชตส่วนตัวกับ OA รหัสใช้ได้ครั้งเดียว ไม่เปลี่ยนบทบาทหรือหน่วยงาน
- ถ้าต้องการตอบรับ/ประมวลผลอัตโนมัติ ให้ตั้ง `PUBLIC_APP_URL` เป็น HTTPS ของ RM และเปิดค่าตอบรับ LINE ในหน้าแม่แบบและการสรุป ค่านี้ปิดเป็นค่าเริ่มต้น
- ข้อความตอบรับเป็นการยืนยันรับข้อมูลและลิงก์ให้เปิดตรวจบนเว็บ ยังไม่ใช่บทสนทนาแก้ข้อมูลทุกช่องใน LINE ไม่ทำให้รายงานเป็น ready อัตโนมัติ
- งานเบื้องหลังมีสถานะสำเร็จ/ล้มเหลว ไม่ใช่ durable queue ที่กู้ทุกงานหลัง process ล่ม ผู้ใช้กดประมวลผลซ้ำได้ งานที่ไม่เสร็จต้องตรวจหลังรีสตาร์ต
- OpenChat และประวัติก่อนบอตเข้ากลุ่มไม่ได้อ้างว่าดึงผ่านเส้นทางนี้ได้ รายงานเก่าใช้ไฟล์ที่ส่งออก/เอกสารที่มีอยู่ ไม่กู้ไฟล์ LINE ที่หมดอายุแล้ว

### ฉบับสรุปตามรอบ

ค่าเริ่มต้นปิด เปิดใน `#report-settings` แล้ว `server/index.js` ตรวจทุก 15 นาที สร้าง snapshot เดือนก่อน และไตรมาส/ปีที่จบตามขอบเขตปีงบประมาณ มี schedule key กันสร้างซ้ำเมื่อรีสตาร์ต มีปุ่มรันเพื่อทดสอบในหน้าแอดมิน ระบบนี้ไม่ส่งข่าวหรือข้อความออก LINE โดยอัตโนมัติ

API ใหม่อยู่หลัง session + CSRF middleware เดิม การแก้ไขใช้ owner/scoped head หรือ role เฉพาะงาน ปิดรอบและฉบับ/version ที่ล้าสมัยป้องกันการแก้ทับ

## การตรวจสอบ

`npm test` ครอบคลุมสิทธิ์, นับแยกหน่วย/แปลงหน่วย, วันจริง/ปีงบประมาณ, ข้อมูลซ้ำ/คืนรายการ, snapshot, DOCX, โครงการ, ปิด/เปิดรอบ, คำขอแก้ไข, LINE signature/link/redelivery, หน่วยงานร่วม, ฟีด, สถานะแอดมิน และวงจรร่างสรุปที่ตรวจยืนยัน

การทดสอบโมเดลร่างใช้ local stub เพื่อทดสอบสัญญา API/สิทธิ์/การอ้างอิง ไม่ใช่ผลประเมินโมเดลจริง การทดสอบ browser อยู่ที่ `npm run test:browser`; ในสภาพแวดล้อมที่แก้ชุดนี้ยังรัน browser ไม่สำเร็จ จึงยังไม่มี screenshot หรือการรับรองการคลิกครบทุกหน้า ควรรันชุด browser และทดสอบกับผู้ใช้ก่อนนำขึ้นใช้งานจริง
