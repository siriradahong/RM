# แม่แบบและร่างรายงานสรุปผล — 18 ตุลาคม 2569

ประยุกต์ข้อเสนอรอบล่าสุดและคำติใน `professor_transcript.md` โดยให้การสรุปผลงานตามฝ่ายและรอบเวลาเป็นแกนหลัก ส่วนโครงการอ้างอิงกิจกรรมที่มีอยู่ ไม่เพิ่มยอดกิจกรรมซ้ำ ข้อมูลและการตอบกลับ AI จำลองจาก HTML ของเพื่อนไม่ถูกนำมาใช้เป็นผลจริง

## สิ่งที่ทำได้แล้ว

| ขั้นตอน | การทำงานจริง |
| --- | --- |
| ตั้งค่า | แอดมินกำหนดแม่แบบตามฝ่ายและประเภทงาน ข้อมูลจำเป็น ชื่อตัวชี้วัด หน่วยนับ วิธีรวม/ค่าสูงสุด หัวข้อรายงาน และเปิด–ปิดแนวโน้มกับส่วนโครงการ |
| ตรวจความพร้อม | เลือกแม่แบบเฉพาะฝ่ายก่อนแม่แบบทุกฝ่าย แสดงข้อมูลขาด รอยืนยัน ไม่มีแม่แบบ และรายการอาจซ้ำ แยกจากยอดที่ใช้ตามแม่แบบได้ทันที |
| เลือกรายงาน | เลือกเดือน ไตรมาสงบประมาณ ปีงบประมาณ หรือช่วงวัน แล้วเลือกเฉพาะรายงานที่ยืนยันและครบตามแม่แบบในสิทธิ์ของผู้ใช้ |
| คำนวณ | นับรหัสกิจกรรมไม่ซ้ำ จับคู่ชื่อตัวชี้วัดและหน่วยตรงกัน ไม่บวกคนรวมกับครั้งบริการ ไม่ใช้ AI คำนวณ |
| สร้างร่าง | ดึงข้อเท็จจริงจากฐานข้อมูลพร้อมรหัสอ้างอิง สร้างข้อความตั้งต้นตามกติกา ผู้จัดทำแก้เนื้อหาและตรวจตัวเลขได้ |
| เลือกรูป | JPEG/PNG จากรายงานที่เลือก ไม่เกิน 4 รูป รูปละ 3 MB เก็บสำเนารูปในฉบับด้วย |
| ยืนยัน | ต้องยืนยันว่าได้ตรวจแล้ว เก็บผู้จัดทำ เวลาตัดข้อมูล รุ่นแม่แบบ รุ่นต้นทาง ตัวเลข รูป และรายการที่ไม่รวม หากต้นทางเปลี่ยนต้องรับทราบหรือจัดทำใหม่ |
| ส่งออก | Word `.docx` จริง พร้อมตารางและรูป; หน้าเว็บมีกราฟแนวโน้มและพิมพ์/บันทึก PDF ผ่านเบราว์เซอร์ Word ใช้ตารางแนวโน้มรายเดือน |
| ตรวจย้อนหลัง | เปิดฉบับเดิม กดตัวชี้วัดให้เน้นรายการอ้างอิง เปิดต้นฉบับ/ประวัติปัจจุบันได้ การแก้ต้นทางไม่เปลี่ยนยอดหรือรูปของฉบับเดิม |

แม่แบบมีตัวอย่างเริ่มต้น 2 แบบที่ **ยังปิดใช้งาน**: ประชุมและอบรม (`ผู้เข้าร่วม / คน`) และเก็บขยะ (`เที่ยวเก็บขยะ / เที่ยว`, `ปริมาณขยะ / ตัน`) ให้แอดมินตรวจร่วมกับหน่วยงานแล้วเปิดใช้หรือสร้างใหม่ ไม่เปิดใช้กติกาตัวอย่างกับข้อมูลจริงโดยอัตโนมัติ

จำนวนคน/รายเป็นยอดตามรายงานแต่ละกิจกรรม ไม่ใช่จำนวนบุคคลไม่ซ้ำ การตรวจรายการอาจซ้ำใช้ชื่อที่ปรับช่องว่างแล้ว + วันที่ + ฝ่ายตรงกัน เป็นเพียงข้อสังเกตให้ผู้จัดทำตรวจ ไม่ใช่การรวมกิจกรรมอัตโนมัติจากความหมายของข้อความ

## วิธีลองครบเส้นทาง

1. แอดมินเปิด **ดูแลระบบ → หน่วยงานและหมวดข้อมูล → รูปแบบรายงาน** แก้แม่แบบประชุมและอบรม เลือกฝ่าย ตรวจชื่อผล/หน่วย แล้วเปิดใช้
2. เจ้าหน้าที่ส่งข้อความพร้อมรูปจาก **เพิ่มข้อมูล** ตรวจข้อมูลที่จำเป็นและตัวเลข เช่น `ผู้เข้าร่วม 19 คน` แล้วกดยืนยันข้อมูลเพื่อสรุป ระบบเสนอข้อมูลที่อ่านได้ให้ก่อน ส่วนที่ไม่พบต้องตรวจเติมจากต้นฉบับ
3. หัวหน้าเปิด **สรุปผลงาน** เลือกหน่วยที่รับผิดชอบและเดือน ดู **ความพร้อมตามแม่แบบ** แล้วกด **สร้างร่างรายงานสรุปผล**
4. เลือกแม่แบบ → **แสดงรายงานในช่วงนี้** ตรวจรายการขาด/อาจซ้ำ เลือกรายงานและรูป → **ต่อไป: ตรวจร่างรายงาน**
5. ตรวจข้อความตั้งต้น เติมปัญหา/แนวทางต่อไปจากข้อเท็จจริง กดชื่อตัวชี้วัดดูข้อมูลอ้างอิง ตรวจรูป แล้ว **ยืนยันฉบับรายงาน**
6. **ส่งออก Word** หรือ **พิมพ์ / บันทึก PDF** กลับมาเปิดฉบับเดิมได้ที่ **สรุปผลงาน → รายงานที่จัดทำไว้**
7. ทดลองแก้รายงานต้นทางที่ไม่ถูกล็อกโดยงานตรวจรับ แล้วเปิดฉบับเดิม: ต้องแจ้งว่าต้นทางเปลี่ยน แต่ตารางและรูปยังเป็นฉบับเดิม หากต้องการข้อมูลล่าสุดให้สร้างฉบับใหม่

หัวหน้าเห็นตามหน่วยที่แอดมินให้รับผิดชอบ เจ้าหน้าที่สรุปเฉพาะข้อมูลที่ตนนำเข้า ผู้บริหารสรุปทั้งสำนัก ผู้มีแค่บทบาทแอดมินตั้งค่าได้แต่ไม่มีสิทธิ์อ่านรายงานสรุป บัญชีหลายบทบาทใช้สิทธิ์ตามบทบาทที่มี การเปิด–ปิดบัญชีไม่ลบประวัติรายงาน

หน้าแดชบอร์ดของฉัน/หน่วยงาน/สำนักแสดงความพร้อมตามแม่แบบเมื่อมีสิทธิ์ในขอบเขตนั้น ยอดกิจกรรมเดิมยังเป็นยอดรายงานยืนยันทั้งหมด ส่วนยอดตามแม่แบบแยกชัดเจนและเข้มงวดกว่า เพราะต้องครบตามกติกาและตรวจรายการอาจซ้ำก่อน

## สิ่งที่ยังต้องทำก่อนอ้างว่าครบระบบตามข้อเสนอ

- **AI:** ผู้ใช้เลือกอ่านไฟล์ในเครื่องก่อน จึงยังไม่เชื่อม AI เขียนร่าง ใช้กติกาและข้อเท็จจริงในฐานข้อมูล อ่าน PDF/Excel/OCR ได้ตาม [ขอบเขตการอ่าน](LOCAL-READING.md) แต่ไม่ได้เข้าใจหรือแยกหลายกิจกรรมอัตโนมัติ และยังไม่มีผลวัดความแม่นยำกับเอกสารจริงของหน่วยงาน
- **แม่แบบทางการ:** ยังไม่ได้รับรายงานจริงของหน่วยงาน รูปแบบ Word เป็นแบบนำร่อง ยังไม่ใช่เอกสารราชการที่ตรวจรับแล้ว แม่แบบกำหนดหัวข้อ/ตัวเลข/ส่วนแสดงผลได้ แต่ยังไม่มีตัวออกแบบหน้ากระดาษอิสระหรืออัปโหลด Word template
- **ขอบเขตประเภทงาน:** เริ่มทดลองสองประเภทข้างต้น ต้องตกลงชื่อผล หน่วยนับ ความหมาย วิธีรวม และข้อมูลที่ขาดกับหน่วยงานก่อนขยายทุกฝ่าย
- **โครงการ:** หัวหน้ากำหนดเป้าหมายเชิงปริมาณพร้อมระบุเอกสาร/หน้าและยืนยันการตรวจแล้วได้ ระบบรวมรายงานยืนยันที่เชื่อมโครงการโดยนับรหัสไม่ซ้ำและใช้ชื่อผล/หน่วยเดียวกัน ก่อนแสดงร้อยละต่อเป้าหมาย หากไม่มีเป้าหมายหรือยังไม่มีค่าที่ตรงกันจะไม่สร้างร้อยละ ยังไม่มีการวิเคราะห์งบประมาณ
- **LINE:** ใช้ webhook/การจัดข้อมูลที่มีอยู่ ต้องมีค่าการเชื่อมต่อและ HTTPS จริง ยังไม่มี AI โต้ตอบอัตโนมัติตามตัวอย่าง HTML
- **สิทธิ์ส่วนเก่า:** สรุป/โครงการ/ฉบับรายงานใหม่มีขอบเขต API ตามบทบาท แต่คลังและแดชบอร์ดเดิมยังอ่านข้อมูลภายในร่วมกันตามข้อตกลงเดิม การปรับทั้งระบบให้จำกัดเฉพาะตนต้องปรับรวมไฟล์ ข่าว และ LINE ด้วย
- **ฉบับยืนยัน:** แก้ผ่าน API ไม่ได้ เก็บสำเนาและ SHA-256 เพื่อระบุเนื้อหาฉบับ ไม่ใช่ลายมือชื่อดิจิทัลหรือระบบป้องกันผู้ดูแลแก้ฐานข้อมูลโดยตรง

## หลักฐานสำหรับนำเสนอและการวัดเวลา

ใช้ข้อมูลชุดเดียวกันและช่วงรายงานเดียวกัน เปรียบเทียบวิธีเดิมกับระบบ ทดลองลำดับสลับกันเพื่อลดผลจากการจำข้อมูล แยกเวลาฝึกออกจากเวลาทำงาน จับเวลาตั้งแต่เริ่มรวบรวมจนได้ฉบับที่ตรวจแล้ว บันทึกเวลาตรวจแก้และความผิดพลาดด้วย ไม่วัดเฉพาะเวลาที่กดสร้างร่าง

| สิ่งที่บันทึก | วิธีเดิม | ใช้ระบบ |
| --- | --- | --- |
| จำนวนรายงานต้นทาง/กิจกรรมจริง | รอเก็บผล | รอเก็บผล |
| เวลารวบรวมและจัดข้อมูล | รอเก็บผล | รอเก็บผล |
| เวลาตรวจแก้และจัดเอกสาร | รอเก็บผล | รอเก็บผล |
| ยอดที่คลาดเคลื่อน/รายการตกหล่นหรือซ้ำ | รอเก็บผล | รอเก็บผล |
| เวลารวม | รอเก็บผล | รอเก็บผล |

ตรวจผลรวมกับชุดเฉลยที่หน่วยงานตรวจแล้ว คิดเวลาที่ลดได้ `(เวลาเดิม − เวลาระบบ) / เวลาเดิม × 100` เมื่อเวลาเดิมมากกว่า 0 ปัจจุบันยังไม่มีผลทดสอบกับผู้ใช้งานจริง จึงยังอ้างเปอร์เซ็นต์ลดเวลาไม่ได้ แบบประเมินเดิมวางแผนผู้ใช้ทั่วไปอย่างน้อย 30 คนและผู้เชี่ยวชาญอย่างน้อย 1 คน; ให้ยืนยันกลุ่มผู้ประเมินตามเกณฑ์อาจารย์อีกครั้ง

ภาพที่ควรจับ: ต้นฉบับรับเข้า → ตรวจข้อมูล/ค่าผลงาน → ความพร้อมตามแม่แบบ → เลือกรายการ → ร่างพร้อมอ้างอิง → ฉบับส่งออก → ประวัติหลังแก้ต้นทาง แล้วผูกภาพเหล่านี้กับ Use Case, Activity และ Sequence Diagram ฉบับล่าสุด คะแนน Complexity และสัดส่วน requirement ต้องประเมินกับรายการที่อาจารย์รับรอง ไม่ถือว่าผ่านเพียงเพราะเพิ่มหน้าจอ

## การตรวจระบบ

`npm test` ตรวจสิทธิ์ ขอบเขตข้อมูล รอบเวลา สูตรรวม/ค่าสูงสุด หน่วยนับ ค่า 0 ข้อมูลขาด อาจซ้ำ แม่แบบชนกัน การแก้ชนกัน ต้นทางเปลี่ยน การคงตัวเลขและรูปเก่า และไฟล์ Word

`npm run test:drafts` ใช้ Chrome และฐานข้อมูลชั่วคราวแยก: ตั้งแม่แบบ → รับรายงาน → เลือกข้อมูล → แก้ร่าง → ยืนยัน → ดาวน์โหลด Word → เปิดมือถือ → ตรวจฉบับเดิมหลังแก้ต้นทาง; ตรวจรูปแบบ Word ทุกหน้าด้วยการแปลงเป็นภาพเพิ่มเติม

`npm run test:browser` และ `npm run test:workflows` ตรวจการใช้งานเดิม ไม่ใช้บัญชีจริง ไม่ส่งข่าว LINE จริง และไม่เพิ่มข้อมูลทดสอบในฐานข้อมูลผู้ใช้
