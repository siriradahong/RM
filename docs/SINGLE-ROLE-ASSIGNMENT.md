# กำหนดตำแหน่งหลักและสังกัดเดียวตามคอมเมนต์อาจารย์

อ้างอิงคำชี้แจงล่าสุดของผู้ใช้เรื่อง Checkbox หลายตำแหน่ง/ฝ่าย และความสับสนระหว่างเจ้าหน้าที่กับประชาสัมพันธ์ ข้อมูลนี้ละเอียดกว่าไฟล์ `professor_transcript.md` เดิมที่สรุปเรื่องสิทธิ์และการเปลี่ยนบุคลากรในภาพรวม

## หน้าแอดมิน

เลือก **ดูแลระบบ → ผู้ใช้งานและสิทธิ์ → เพิ่มบัญชี/แก้ไข** แล้วเลือกตามลำดับ:

1. **ตำแหน่ง/บทบาทหลัก** เลือกได้หนึ่งอย่างจาก Dropdown
2. **ฝ่ายหลัก** แสดงเมื่อบทบาทนั้นต้องมีฝ่าย
3. **งาน/ศูนย์หลัก** แสดงเฉพาะงานในฝ่ายที่เลือก เมื่อเปลี่ยนบทบาทหรือฝ่ายจะล้างตัวเลือกที่ไม่สอดคล้อง

| บทบาทหลัก | ฝ่าย | งาน/ศูนย์ | สิทธิ์สำคัญ |
|---|---|---|---|
| เจ้าหน้าที่ | หนึ่งฝ่าย | หนึ่งงาน | รายงานของตนและหลักฐานตามสิทธิ์ |
| ประชาสัมพันธ์ | หนึ่งฝ่าย | หนึ่งงาน | ส่งรายงานของตนภายใต้บทบาท PR และจัดการข่าวตามคิว ไม่ต้องเพิ่มบทบาท staff |
| หัวหน้าฝ่าย | หนึ่งฝ่าย | ดูแลทั้งฝ่าย | ขอบเขตหัวหน้าได้จากฝ่ายเดียวที่เลือก |
| หัวหน้าศูนย์ | หนึ่งฝ่าย | หนึ่งงาน/ศูนย์หลัก | ดูแลศูนย์นั้นและงานย่อยในโครงสร้าง |
| ผู้บริหาร | ระดับสำนัก | ไม่เลือกงานซ้ำ | ภาพรวมสำนัก |
| แอดมิน | ระดับสำนัก | ไม่เลือกงานซ้ำ | บัญชี โครงสร้าง ค่ากลาง และ audit ตามนโยบายเดิม |

รายการฝ่ายและงานใช้โครงสร้างที่มีอยู่ในระบบจากภาพโครงสร้างของหน่วยงานที่ผู้ใช้ให้ไว้ ไม่สร้างฝ่ายใหม่ตามชื่อบทบาท ช่องชื่อตำแหน่งตามข้อมูลบุคลากรเป็นข้อความประกอบ ไม่เพิ่มสิทธิ์ในระบบ

## การบันทึกและการรับรอง

- ฝั่ง API ตรวจบทบาทหนึ่งอย่าง ขอบเขตฝ่าย/ศูนย์ไม่เกินหนึ่งค่า และตรวจว่าหน่วยงาน/งานเปิดใช้และอยู่ในสังกัดเดียวกัน
- บทบาทเจ้าหน้าที่/PR ไม่รับขอบเขตหัวหน้าแฝง ผู้บริหาร/แอดมินไม่บันทึกฝ่ายหรืองานซ้อน บทบาทหัวหน้าไม่แยกฝ่ายปฏิบัติงานออกจากฝ่ายที่ดูแล
- การรับรองจาก LINE เปลี่ยนบทบาทเดิมเป็นบทบาทที่รับรองเพียงอย่างเดียว และถอนเซสชันเดิม ผู้ขอเริ่มจาก staff จนกว่าจะผ่านการรับรอง
- การมอบอำนาจชั่วคราวยังเป็นรายการแยกที่มีผู้ให้ ผู้รับ วันที่เริ่ม–สิ้นสุด และประวัติ ไม่เพิ่มบทบาทหลักหรือทำให้แอดมินติ๊กสังกัดถาวรได้หลายแห่ง

## บัญชีเดิม

ไม่เลือกบทบาทแทนบุคลากร ไม่ลบรายงาน ไม่ย้ายเจ้าของรายงาน และไม่เขียนทับบทบาทเก่าโดยอัตโนมัติ หากบัญชีเดิมมีหลายบทบาทหรือหลายขอบเขตหลัก ระบบจะแจ้งให้แอดมินตรวจและเลือกใหม่:

- ผู้ใช้ทั่วไปเห็นหน้ารอกำหนดตำแหน่งหลักและออกจากระบบได้ โดยยังไม่รวมสิทธิ์จากบทบาทเก่า
- แอดมินเดิมที่มีหลายบทบาทยังเข้าจัดการบัญชีเพื่อแก้บทบาทตนเองได้ แต่ไม่ใช้สิทธิ์รายงานที่เคยผสมไว้
- แอดมินเห็นป้ายรอตรวจในรายชื่อผู้ใช้ เลือกบทบาทและสังกัดเดียวโดยชัดแจ้งก่อนบันทึก
- หลังบันทึก ถอนเซสชันเก่าและลงทะเบียนประวัติ/การแก้ไขตามกลไกเดิม รายงานและฉบับส่งออกเดิมอยู่ครบ
- ไม่ต้องย้าย schema ฐานข้อมูล เก็บข้อมูลเดิมไว้และคำนวณสถานะรอตรวจจากค่าที่มีอยู่
