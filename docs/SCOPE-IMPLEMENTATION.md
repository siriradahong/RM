# การปรับระบบตาม PDF ครบระยะ 1–3

อ้างอิงเอกสาร “สโคปงานระบบที่เพิ่มคร่าวๆ” ลงวันที่ 17 ตุลาคม 2569 และคำยืนยันให้ทำทุกระยะ รวมทั้งเปลี่ยนจากอ่านร่วมกันเป็นจำกัดตามบทบาท งานนี้อยู่ใน `codex/rm-clear-workflows-20261018` ไม่รวม PR #1 และไม่ merge เข้า main

## เส้นทางใช้งานหลัก

1. **เพิ่มข้อมูล**: พิมพ์รายงานช่องเดียวเหมือน LINE พร้อมแนบ PDF, Word `.docx`, Excel `.xlsx` หรือรูป เลือกเก็บไว้ค้นหาโดยไม่สร้างกิจกรรมได้ ข้อความพร้อมรูปแนบกับรายงานเดียวกัน
2. **ตรวจข้อมูลรายงาน**: อ่านสรุป แก้เฉพาะจุด เก็บต้นฉบับและหลักฐาน ยืนยันพร้อมสรุปเมื่อข้อมูลจำเป็นครบ ตัวเลขจากภาพถ่ายคนไม่ถูกประมาณเอง
3. **ผู้ร่วมงาน ชุมชน และการนำข้อมูลไปใช้**: พับไว้ในรายละเอียดรายงาน ระบุบทบาทผู้ปฏิบัติงานจริงและฝ่ายร่วม ผู้มีชื่อยืนยันบทบาทตนเอง การสรุปบุคลากรต้องมีเจ้าของรายงานยืนยันข้อเท็จจริงและตัวเลขด้วย
4. **โครงการและงาน**: หัวหน้าฝ่าย/ศูนย์หรือผู้บริหารมอบหมาย ผู้รับงานอัปเดตรายวัน ส่งรายงานเป็นหลักฐาน หรือขอเลื่อนกำหนด หัวหน้าตรวจรับก่อนปิดโครงการ
5. **พื้นที่งานของฉัน**: เลือกหัวข้อจากรายการเดียว ได้แก่ แจ้งเตือน นัดหมาย ข้อเสนอจากข้อความ พื้นที่และชุมชน แผนและงบประมาณ คำขอ/มอบอำนาจ ผลงานรายบุคคล และรายงานตามรอบ โดยแสดงเฉพาะหัวข้อที่เกี่ยวข้องกับบทบาท
6. **จัดการข่าว**: รับคิวจากรายงานเดิม ปิดตัวระบุบุคคลตามรูปแบบที่ตรวจพบ เสนอข้อความจากข้อเท็จจริง ประชาสัมพันธ์ตรวจข้อความและรูปก่อนยืนยันเผยแพร่ การส่ง LINE เป็นขั้นแยก
7. **ดูแลระบบ**: คง 3 แท็บหลัก ค่ามาตรฐานสำนักและงานอัตโนมัติอยู่ในหน่วยงานและหมวดข้อมูล ประวัติการแก้ไขแยกหน้า

## สิ่งที่ต้องตั้งค่าจริง ไม่ใช่ผลสาธิต

- **LINE**: ต้องมี LINE Login และ Messaging API ของหน่วยงาน ใช้ provider เดียวกัน ตั้ง secret/token, กลุ่ม และ HTTPS webhook/callback ใน `.env` ก่อน เปิดผู้ช่วย LINE และการแจ้งเตือนจากค่ากลาง ระบบไม่ได้อ้างว่าเชื่อม LINE จริงแล้วจากการตั้งค่าว่าง การทดสอบใช้คำตอบจำลอง ไม่ส่งข้อความจริง
- **โมเดล AI**: ตอนนี้ใช้การอ่านและกติกาในเครื่องตามที่เลือกไว้ รองรับ Ollama ผ่าน `OLLAMA_MODEL`/`OLLAMA_BASE_URL` เมื่อผู้ติดตั้งจัดหาโมเดลที่เหมาะสมแล้ว มีเกณฑ์ความมั่นใจและตรวจข้อความอ้างอิง ค่าที่ไม่ตรงไม่ถูกนำมาใช้ โมเดลขัดข้องแจ้งเตือนและใช้การอ่านในเครื่องต่อ ไม่มี Gemini และไม่มี fine-tuning
- **OCR**: ใช้ไฟล์ภาษาไทย/อังกฤษในเครื่อง ต้องติดตั้งชุดภาษาเมื่อย้ายเครื่อง รูปถ่ายคนเป็นหลักฐาน ไม่อนุมานจำนวนผู้รับบริการ
- **แบบงานบุคคล/เป้าหมาย/พิกัด/งบ**: ยังไม่ได้รับแบบประเมินทางการหรือแผนงบที่ยืนยัน ไม่มีการสร้างตัวเลขและทะเบียนสมมติในฐานข้อมูลใช้งาน แอดมิน/หัวหน้ากำหนดจากเอกสารจริงก่อนอ้างว่าใช้ส่งงานบุคคลได้ แบบในภาพทดสอบระบุว่าเป็นเอกสารทดสอบ
- **ความเป็นส่วนตัว**: การปิดเลขบัตร โทรศัพท์ และชื่อผู้รับบริการตามรูปแบบช่วยลดงานตรวจ ไม่รับประกันตรวจพบทุกชื่อหรือทุกรูป ประชาสัมพันธ์ต้องตรวจและยืนยันก่อนเผยแพร่
- **รายงานอัตโนมัติ**: เปิดเตือนในเว็บและเตรียมรายงานตามรอบเป็นค่าเริ่มต้น แต่เกิดงานตามรอบได้เมื่อเปิดเซิร์ฟเวอร์อยู่ การส่ง LINE ปิดไว้จนตั้งค่า การลบอัตโนมัติปิดไว้และยังไม่กำหนดจำนวนวัน
- **พื้นที่/เฝ้าระวัง**: กราฟพิกัดใช้ทะเบียนจริง ไม่ใช่เส้นเขตการปกครอง สัญญาณไข้เลือดออกคือรายงานตั้งแต่ 2 กิจกรรมในชุมชนใน 7 วัน ไม่ใช่ผลวินิจฉัยหรือยืนยันการระบาด ต้องเปิดต้นทางตรวจ
- **การย้ายรุ่น**: migration 11 เพิ่มข้อมูลโดยรักษา users/activities/files/inbox/news/projects/ฉบับเดิมไว้ สำรองก่อนเริ่มระบบ รุ่นเก่าที่มีโครงการเสร็จแต่ไม่มีวันปิดจะไม่ถูกสมมติวันปิดเพื่อรวมยอดตามรอบ
