# การอ่านไฟล์ในเครื่อง

รุ่น 18 ตุลาคม 2569 ตามที่เลือกใช้การอ่านในเครื่องก่อน ยังไม่มีบริการ AI ภายนอก

## เริ่มใช้งาน

1. ติดตั้งด้วย `npm ci` บน Node.js 24.13 ขึ้นไป
2. รัน `npm run ocr:setup` ครั้งแรกเพื่อดาวน์โหลดภาษาไทยและอังกฤษจากโครงการ Tesseract ทางการ ต้องใช้อินเทอร์เน็ตเฉพาะขั้นตอนนี้
3. รัน `npm run build` แล้ว `npm start`
4. ดูสถานะใน **ดูแลระบบ → หน่วยงานและหมวดข้อมูล**

โมเดลอยู่ใน `data/ocr` ซึ่งไม่ขึ้น GitHub กำหนดตำแหน่งอื่นด้วย `OCR_MODEL_DIR` ได้ เมื่อติดตั้งบนเครื่องใหม่ต้องติดตั้งโมเดลด้วย แม้จะนำฐานข้อมูลและไฟล์แนบกลับคืนแล้วก็ตาม

## สิ่งที่อ่านได้

| ต้นทาง                 | วิธีอ่านและขอบเขต                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------- |
| ข้อความที่พิมพ์หรือวาง | กติกาช่วยหาเรื่อง วันที่ สถานที่ ผู้ปฏิบัติงาน ผล และตัวเลขที่มีชื่อผล/หน่วยชัดเจน          |
| PDF ที่มีข้อความ       | อ่านข้อความไม่เกิน 30 หน้าแรก ไม่รันสคริปต์ในเอกสาร                                         |
| PDF สแกน               | หน้าที่ไม่พบข้อความใช้ OCR ไทย/อังกฤษ ไม่เกิน 5 หน้าสแกนต่อไฟล์                             |
| Excel `.xlsx`          | อ่านค่าเซลล์และผลสูตรที่บันทึกไว้ ไม่รันสูตร อ่าน 10 แผ่นงานแรก แผ่นละ 2,000 แถว/40 คอลัมน์ |
| รูปเอกสาร              | เลือก “อ่านตัวหนังสือในรูปเอกสารด้วย” ในหน้าตรวจข้อมูลแล้วกดอ่านต้นฉบับ                     |
| รูปถ่ายกิจกรรม         | แนบเป็นหลักฐาน ไม่เดาหรือรวมจำนวนคนจากภาพ                                                   |
| Excel `.xls`           | เก็บต้นฉบับได้ แต่ต้องบันทึกเป็น `.xlsx` ก่อนอ่าน                                           |

อ่านต่อครั้งไม่เกิน 120 วินาที ข้อความรวม 60,000 ตัวอักษร ส่วนที่อ่านเกินขอบเขตหรืออ่านไม่ได้จะแจ้งให้แบ่งเอกสาร ต้นฉบับยังคงอยู่ ไฟล์ติดรหัสผ่าน/เสียหายอาจอ่านไม่ได้ ไม่รับประกันความแม่นยำ OCR และยังไม่ได้วัดความแม่นยำกับชุดเอกสารจริงของหน่วยงาน

## ส่ง → ตรวจ → ยืนยัน

หน้า **เพิ่มข้อมูล** รับข้อความและไฟล์พร้อมกัน แล้วเปิด **ตรวจข้อมูลรายงาน** พร้อมข้อเสนอที่อ่านได้ ระบบเติมเฉพาะช่องที่ยังไม่มีค่า พร้อมเก็บข้อความอ้างอิงให้ตรวจใน “ดูข้อความที่อ่านได้และจุดที่ต้องตรวจ” ไม่เขียนทับข้อมูลเดิมที่เจ้าหน้าที่กรอกและไม่เปลี่ยนสถานะเป็นยืนยันเอง

กติกาช่วยอ่านเป็นข้อเสนอ ไม่ได้เข้าใจเอกสารทุกแบบหรือแยกหลายกิจกรรมเป็นหลายรายงานอัตโนมัติ หาก Excel มีหลายกิจกรรม ต้องแยกรายงานก่อนรวมยอด ถ้าพบชื่อตัวเลขเดียวกันหลายค่า ระบบจะเตือนแทนการบวกเอง ช่วงวันที่ใช้วันเริ่มกิจกรรมจัดรอบและเตือนให้ตรวจรายละเอียด ระบบไม่เปลี่ยนฝ่าย/งานจากข้อความอัตโนมัติ เพราะผู้ส่งอาจรายงานแทนหรือเอกสารกล่าวถึงหลายฝ่าย

**บันทึกไว้ก่อน** เก็บเป็นรอยืนยัน ส่วน **ยืนยันข้อมูลเพื่อสรุป** ตรวจข้อมูลจำเป็นก่อนรวมยอด หากอ่านไม่พบให้แก้เฉพาะจุดจากต้นฉบับ การอ่านซ้ำใช้ได้กับรายการรอยืนยันที่มีสิทธิ์แก้ไข และป้องกันการใช้ผลอ่านเมื่อรายการเปลี่ยนรุ่นระหว่างอ่าน

การเลือก **เก็บไว้ค้นหาเท่านั้น — ไม่รวมในสรุปผลงาน** เก็บข้อความ/ไฟล์โดยไม่สร้างกิจกรรม ไม่เริ่มสรุปหรือรวมตัวเลข

## ซอฟต์แวร์ที่ใช้

- [PDF.js](https://github.com/mozilla/pdf.js) อ่าน PDF
- [ExcelJS](https://github.com/exceljs/exceljs) อ่าน `.xlsx`
- [Tesseract.js](https://github.com/naptha/tesseract.js) และ [โมเดล tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast) อ่านภาพในเครื่อง

ค่าเริ่มต้นไม่ต้องมี API key และไม่ส่งเอกสารไปผู้ให้บริการ AI การสร้างร่างสรุปยังใช้ข้อความตามกติกาและตัวเลขที่คำนวณจากฐานข้อมูล ดู [คู่มือแม่แบบและร่างรายงาน](SUMMARY-DRAFTS.md)

## การขยายตาม PDF

รองรับ Word `.docx` โดยอ่านเฉพาะข้อความใน document.xml ไม่เรียก macro หรือ external relationship ส่วน `.doc` และ `.xls` เก็บต้นฉบับได้เฉพาะชนิดที่อนุญาต แต่ควรแปลงเป็น `.docx`/`.xlsx` เพื่ออ่านข้อความ

ยังใช้การอ่านในเครื่องเป็นค่าเริ่มต้น หากจัดเตรียม Ollama เองแล้วกำหนด `OLLAMA_MODEL` และ `OLLAMA_BASE_URL` ระบบจะเสนอข้อมูลที่มีข้อความอ้างอิงและช่วยเรียบเรียงร่างที่คนต้องตรวจ ดู [ขอบเขตฉบับล่าสุด](SCOPE-IMPLEMENTATION.md) ไม่ต้องตั้ง API key และไม่มีการดาวน์โหลดโมเดลอัตโนมัติ
