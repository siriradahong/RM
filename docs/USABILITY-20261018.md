## ฟังก์ชันที่เพิ่มและเชื่อมกับข้อมูลจริง

**ยืนยันรายการซ้ำ**: เปิดรายงาน → “ตรวจรายการซ้ำ” ระบบเสนอชื่อ/วันที่/ฝ่ายตรงกันให้เทียบ ผู้มีสิทธิ์เลือกรายงานหลักที่ยืนยันในฝ่ายเดียวกัน ระบุเหตุผล แล้วกดยืนยัน ต้นฉบับ ไฟล์ ตัวเลข และประวัติยังอยู่ สถานะพร้อมสรุปเดิมไม่ถูกลบ แต่มีเครื่องหมายแยกเพื่อไม่รวมยอด ยกเลิกการระบุว่าซ้ำได้ตามสิทธิ์ ทุกครั้งเพิ่ม version และ audit ไม่อนุญาตอ้างตัวเอง อ้างรายการซ้ำเป็นหลัก สร้างสายอ้างอิงซ้อน หรือเปลี่ยนรายงานที่ล็อกด้วยงานตรวจรับ

ไม่นำรายการที่ยืนยันว่าซ้ำมารวมในแดชบอร์ด รายงานสรุป ความพร้อมแม่แบบ การสร้างฉบับใหม่ หรือผลสะสมโครงการ ฉบับยืนยันเก่ายังคง snapshot เดิมและแจ้งว่าต้นทางเปลี่ยน ระบบตรวจ “อาจซ้ำ” ยังเป็นกติกาชื่อ/วันที่/ฝ่าย ไม่ใช่การพิสูจน์ความหมายอัตโนมัติ

**วิธีสรุปกลาง**: แดชบอร์ดและรายงานใช้กติกาตัวชี้วัดเดียวกัน เลือกแม่แบบเฉพาะฝ่ายก่อนแม่แบบทุกฝ่าย ใช้รวมค่าหรือค่าสูงสุดตามแม่แบบ แยกชื่อผล หน่วย และวิธีรวม ตัวเลขเพิ่มเติมที่ไม่ตรงแม่แบบรวมค่าตามชื่อ/หน่วย ไม่รวมคนกับครั้งบริการ กดตัวเลขเปิดเฉพาะรายงานต้นทางที่ใช้คำนวณได้ ค่าที่ไม่พบยังเป็นไม่มีข้อมูล ส่วนค่าที่รายงาน 0 ยังคงเป็น 0

**ปฏิทิน**: ใช้วันที่กิจกรรมจริงเท่านั้น ไม่มีการสมมติเวลา นัดหมาย หรือแจ้งว่านัดชนกันหากไม่มีข้อมูลเวลา วันที่ยังไม่ระบุค้นจากคลังได้ ปฏิทินจำกัดคำขอไม่เกิน 63 วัน และแสดงไม่เกิน 500 รายการพร้อมคำเตือนให้กรองฝ่ายเพิ่ม

**ค้นหา**: ค้นชื่อ พื้นที่ ผล ผู้ปฏิบัติงาน ข้อความต้นฉบับ และข้อความที่อ่านในเครื่องแล้ว เอกสารที่ยังไม่เคยอ่านต้องเปิดรายงานและกดอ่านก่อนจึงค้นเนื้อในได้ ไฟล์เก็บไว้ค้นหายังค้นจากชื่อ/คำค้น/ข้อความที่ฝาก ไม่เริ่มอ่านหรือสร้างกิจกรรมโดยอัตโนมัติ

## สิทธิ์และบริการภายนอก

สิทธิ์ยังตรวจที่ backend ทุกบัญชีภายในอ่านข้อมูลร่วมกัน เจ้าหน้าที่แก้เฉพาะตน หัวหน้าแก้เฉพาะฝ่ายที่ได้รับสิทธิ์ แอดมินไม่ได้สิทธิ์แก้รายงานทุกฝ่ายเพิ่มโดยอัตโนมัติ รายงานสรุป/ฉบับและโครงการยังใช้ขอบเขตเฉพาะบทบาทจาก main ไม่มีตัวสลับบทบาท ไม่มี Facebook API

ใช้การอ่าน PDF/Excel/OCR ในเครื่องตามที่ผู้ใช้เลือกไว้ ดู [คู่มือ](LOCAL-READING.md) ไม่ต้องมี API key แต่ OCR ต้องติดตั้งภาษา (`npm run ocr:setup`) ไม่มีการเชื่อม AI ภายนอกหรือ Ollama จาก PR #1 ร่างสรุปใช้ข้อเท็จจริงและกติกา ไม่มี Gemini หรือการ fine-tune ประชาสัมพันธ์ยังตรวจข้อความและเลือกรูปก่อนเผยแพร่เอง

LINE รับผ่าน webhook เดิมและกัน event ซ้ำ ต้องตั้งค่า Channel/กลุ่มและ HTTPS ก่อนใช้งานจริง สถานะ “ตั้งค่าแล้ว” ไม่ใช่ผลทดสอบการรับส่งจริง ไม่ส่งข้อความ LINE จากชุดทดสอบ

## โครงสร้างฐานข้อมูลและไฟล์หลัก

Migration 10 เพิ่ม `activities.duplicate_of`, `duplicate_reason` และดัชนี เก็บตาราง/ID/ไฟล์เดิม ไม่มีการเติมข้อมูลสาธิตในฐานข้อมูลจริง

- `src/dashboard.jsx`, `src/calendar.jsx`, `src/duplicate-review.jsx`: หน้าสรุป ปฏิทิน และตรวจซ้ำ
- `src/reports.jsx`, `src/projects.jsx`, `src/extraction.jsx`, `src/styles.css`: เชื่อมหน้าที่มีอยู่และปรับความกระชับ
- `server/analytics.js`, `server/insight-routes.js`: คำนวณตามแม่แบบและตรวจสิทธิ์ปฏิทิน/ตรวจซ้ำ
- `server/data-routes.js`, `report-routes.js`, `summary-engine.js`, `project-routes.js`, `db.js`, `app.js`: เชื่อมยอด ค้นหา สิทธิ์ และ migration
