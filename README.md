# ระบบบูรณาการข้อมูลและสรุปผลการปฏิบัติงาน

เว็บสำหรับสำนักสาธารณสุขและสิ่งแวดล้อม เทศบาลนครขอนแก่น ใช้ **React + Vite, Node.js + Express API และ SQLite** เก็บข้อมูลถาวรในเครื่อง รองรับคอมพิวเตอร์ แท็บเล็ต และมือถือ

ระบบหลักเชื่อมฐานข้อมูลจริง ไม่สร้างบัญชี demo อัตโนมัติ ไม่มีการสลับบทบาทเอง และไม่ใส่จำนวนงานจำลองเมื่อเริ่มระบบ เริ่มด้วยหน่วยงานและหมวดข้อมูลพื้นฐานเท่านั้น รายการงาน ข่าว และไฟล์เริ่มว่าง ต้นแบบเดิมอยู่ใน `archive/` และไม่ถูก build หรือเปิดให้บริการ

อัปเดตหน้าจอ 18 ต.ค. 2569: รวมช่องทางรับข้อมูล/ข่าวไว้ในเมนูแม่ เพิ่มปฏิทินจากรายงานและการยืนยันรายการซ้ำ แดชบอร์ดเลือกรอบเวลาและใช้วิธีรวมตามแม่แบบ ดู [ขอบเขตและผลตรวจรับรอบนี้](docs/USABILITY-20261018.md)

## เริ่มใช้งาน

ใช้ Node.js **24.13 ขึ้นไปในสาย 24 LTS** และ npm โดยใช้ `node:sqlite` ของ Node โดยตรง (Node 24.13 ยังแสดง ExperimentalWarning สำหรับโมดูลนี้)

```sh
npm ci
cp .env.example .env
npm run admin:create
npm run build
npm start
```

เปิด **http://localhost:3001**

`admin:create` ถามชื่อผู้ใช้และชื่อผู้ดูแล สร้างรหัสผ่านสุ่ม 24 ตัวอักษร และเขียนลง `.first-admin.txt` ซึ่งเข้าถึงได้เฉพาะเจ้าของไฟล์และไม่ขึ้น Git ข้อมูลเข้าสู่ระบบไม่ถูกพิมพ์ลง log หากใช้ provisioning กำหนด `ADMIN_USERNAME`, `ADMIN_NAME`, `ADMIN_PASSWORD` ผ่าน environment ได้ ไม่มีรหัสผ่านตายตัวในโค้ด

เข้าสู่ระบบด้วยแอดมิน → **ดูแลระบบ → ผู้ใช้งานและสิทธิ์ → เพิ่มบัญชี** เพื่อสร้างบัญชีจริง เปลี่ยนรหัสผ่านของตนเองจากบัญชีมุมขวาบน หากลืมรหัสผ่านให้แอดมินตั้งใหม่ ไม่มีการสมัครบัญชีสาธารณะ

พัฒนา: `npm run dev` เปิด Vite ที่ http://localhost:5173 และ Express ที่ http://localhost:3001 โดย Vite proxy `/api` ไป Express

## มือถือใน Wi-Fi เดียวกัน

1. เปิดระบบบนคอมพิวเตอร์ด้วย `npm start` หลัง build
2. หา IPv4 ของคอมพิวเตอร์ เช่น `192.168.1.20`
3. เพิ่ม `http://192.168.1.20:3001` ใน `APP_ORIGIN` ของ `.env` คั่นด้วยจุลภาค แล้วเริ่มระบบใหม่
4. เปิด `http://192.168.1.20:3001` บนมือถือที่อยู่ Wi-Fi เดียวกัน ไฟร์วอลล์ต้องอนุญาตพอร์ต 3001

```dotenv
HOST=0.0.0.0
PORT=3001
APP_ORIGIN=http://localhost:3001,http://localhost:5173,http://192.168.1.20:3001
```

ฐานข้อมูลอยู่บนเครื่องที่เปิดเซิร์ฟเวอร์ เมื่อเครื่องปิด มือถือจะเข้าไม่ได้ การเปิดผ่านอินเทอร์เน็ตต้องมีเซิร์ฟเวอร์และ HTTPS ดู [คู่มือติดตั้ง](docs/DEPLOYMENT.md) GitHub Pages ไม่สามารถรัน backend ของระบบนี้ได้

## 5 บทบาท

| บทบาท                   | สิทธิ์เฉพาะ                                                  |
| ----------------------- | ------------------------------------------------------------ |
| เจ้าหน้าที่ (`staff`)   | นำเข้าไฟล์/สร้างรายงานตามฝ่ายและงานประจำ แก้ไขรายงานของตนเอง |
| หัวหน้าฝ่าย (`head`)    | สร้างและแก้ไขงานในหน่วยงานที่ได้รับมอบขอบเขต                 |
| ผู้บริหาร (`executive`) | อ่านข้อมูล ดูภาพรวมและหลักฐานย้อนหลัง                        |
| ประชาสัมพันธ์ (`pr`)    | เลือกต้นทาง จัดทำร่าง ยืนยันข่าว และส่ง LINE                 |
| ผู้ดูแลระบบ (`admin`)   | บัญชี บทบาท สังกัด ขอบเขตหัวหน้า หมวดข้อมูล และ audit        |

หนึ่งบัญชีมีหลายบทบาทได้ ทุกบัญชีที่เปิดใช้งานอ่านข้อมูลภายในร่วมกันได้ ตรวจสิทธิ์ที่ API ไม่ใช่แค่ซ่อนเมนู แอดมินไม่ได้สิทธิ์แก้รายงานทั้งหมดโดยอัตโนมัติ เมื่อแก้ไขสิทธิ์/รหัสผ่าน/สถานะบัญชี session ของบัญชีนั้นจะถูกยกเลิก

## ฟังก์ชันที่ทำงานจริง

ผู้ดูแลระบบใช้หน้า **ดูแลระบบ** 3 แท็บ: **ผู้ใช้งานและสิทธิ์**, **หน่วยงานและหมวดข้อมูล** และ **การเชื่อมต่อ LINE** เมื่อเปลี่ยนแท็บ URL จะเก็บแท็บที่เลือกไว้ จึงรีเฟรชหรือส่งลิงก์หน้าที่ต้องการได้ รายชื่อผู้ใช้แสดงฝ่าย งานประจำ และขอบเขตหน่วยงานของหัวหน้า

หน้า **ประวัติการแก้ไขข้อมูล** แยกจากหน้าดูแลระบบ ค้นหา กรองประเภทรายการและวันที่ได้ รายละเอียดแสดงเฉพาะช่องที่เปลี่ยนพร้อมค่าเดิม/ค่าใหม่แบบอ่านอย่างเดียว ส่วนแท็บ LINE แสดง Group ID และเวลารับ–ส่งจริงล่าสุด ไม่เปิดเผย Channel secret หรือ Access token การแก้การเชื่อมต่อยังทำผ่าน `.env` บนเซิร์ฟเวอร์แล้วเริ่มระบบใหม่ สถานะตั้งค่าแล้วไม่ใช่ผลทดสอบการติดต่อ LINE

- เข้าสู่ระบบด้วย password hash (scrypt), session ในฐานข้อมูล, HttpOnly/SameSite cookie, CSRF และตรวจ Origin
- Rate limit และพักบัญชีเมื่อกรอกรหัสผ่านผิดหลายครั้ง
- คลังงานค้นหา กรองหน่วยงาน วันที่ ประเภท สถานะ แหล่งที่มา และแบ่งหน้า
- อัปโหลดและดาวน์โหลดไฟล์จริง: PDF, XLS/XLSX, JPG/PNG/WebP ไม่เกิน 20 MB ต่อไฟล์ ตรวจชนิดจากเนื้อไฟล์ เข้าถึงได้เฉพาะผู้เข้าสู่ระบบ
- แยกฝากเอกสารกับหลักฐานงาน หลายไฟล์/ข้อความเชื่อมหนึ่งกิจกรรมได้
- แก้ไขตามสิทธิ์ พร้อม version ป้องกันการเขียนทับข้อมูลเก่า
- แดชบอร์ดคำนวณเฉพาะงาน `ready` แยกผลตามชื่อและหน่วยนับ ไม่รวมคน ตัน และครั้งบริการเข้าด้วยกัน
- ข่าวแยกจากรายงานต้นทาง เลือกรูปและรูปปก บันทึกร่าง Preview และยืนยันเผยแพร่บนฟีดภายใน
- บัญชี โครงสร้างหน่วยงาน หมวดข้อมูล และ audit พร้อมค่าเดิม/ค่าใหม่

## ฝ่าย งานในสังกัด และประเภทงาน

โครงสร้างตามผังของหน่วยงานประกอบด้วย 2 ส่วน 8 ฝ่าย และ 1 กลุ่มงาน รวม 30 งานในสังกัด โดยฝ่ายบริหารงานทั่วไปขึ้นตรงกับสำนัก รายการทั้งหมดอยู่ใน `server/organization.js` และย้ายเข้าฐานข้อมูลอัตโนมัติด้วย migration 3 เพียงครั้งเดียว โดยเก็บ ID ของ 3 ฝ่ายเดิมและข้อมูลผู้ใช้/รายงานไว้

- ผู้ดูแลระบบกำหนด **สังกัด → งานที่รับผิดชอบ** ที่ **ดูแลระบบ → ผู้ใช้งานและสิทธิ์ → เพิ่ม/แก้ไขบัญชี** บัญชีที่มีบทบาทเจ้าหน้าที่ต้องมี 1 ฝ่าย และ 1 งานที่เปิดใช้ในฝ่ายนั้น
- พนักงานจะเห็นฝ่ายและงานที่แอดมินกำหนดในหน้านำเข้าและฟอร์มรายงานแบบอ่านอย่างเดียว API ตรวจซ้ำเพื่อป้องกันการเปลี่ยนผ่านคำขอเอง ผู้ที่มีบทบาทหัวหน้าฝ่ายร่วมด้วยยังใช้สิทธิ์ในฝ่ายที่ได้รับมอบขอบเขตได้
- หน้านำเข้าใช้ช่อง **ชื่อเรื่อง** แทนคำสำคัญ ชื่อเดียวกันถูกเก็บเป็นชื่อเอกสารทุกไฟล์ในชุดและนำไปแสดงในช่องชื่อเรื่องของหน้าสร้างรายงานถัดไป รวมถึงเมื่อรีโหลดหน้านั้น
- Migration 4 เพิ่มงานประจำในบัญชีและงานในไฟล์ บัญชีเดิมยังไม่ถูกสุ่มกำหนดงาน แอดมินต้องเลือกงานให้ก่อนสร้างรายงานหรือนำเข้าไฟล์ใหม่ การอ่านข้อมูลและแก้รายละเอียดรายงานเก่ายังทำได้โดยรักษาฝ่าย/งานเดิมไว้
- **ประเภทงาน** เป็นรายการใช้ร่วมกันทุกฝ่าย เจ้าหน้าที่และหัวหน้าฝ่ายกด **เพิ่มประเภทงาน** ในฟอร์มได้ ชื่อใหม่จะถูกบันทึกและเลือกทันที โดยไม่ล้างข้อมูลที่กรอกไว้ ระบบไม่รับชื่อซ้ำ
- ผู้ดูแลระบบเข้า **ดูแลระบบ → หน่วยงานและหมวดข้อมูล** เพื่อเพิ่ม/แก้ไขส่วน ฝ่าย กลุ่มงาน งานในสังกัด และประเภทงาน หรือปิดใช้งานรายการที่ไม่ใช้แล้ว ข้อมูลงานเก่าจะเก็บการอ้างอิงไว้
- สิทธิ์รายงานอิงฝ่ายและงานประจำของเจ้าหน้าที่ รวมถึงขอบเขตฝ่ายของหัวหน้า ผู้ดูแลกำหนดฝ่ายและงานใหม่ให้บัญชีได้ในแท็บ **ผู้ใช้งานและสิทธิ์** ส่วนใช้จัดกลุ่มโครงสร้าง ไม่ใช้แทนฝ่ายในการมอบสิทธิ์

## ส่งรายงานจากหน้าเดียว

เมนูเพิ่มข้อมูลมีช่องข้อความและพื้นที่แนบ PDF/Excel/รูปภาพในหน้าเดียว ส่งข้อความอย่างเดียว ไฟล์อย่างเดียว หรือทั้งสองแบบได้ ปุ่มส่งรายงานบันทึกต้นฉบับพร้อมเวลารับข้อมูลเป็นรายการรอตรวจทันที ส่วนตัวเลือกฝากไฟล์ไว้ค้นหาเท่านั้นจะไม่สร้างกิจกรรม

หน้าตรวจข้อมูลแสดงสรุปและให้กดแก้ไขตรงรายการ ไม่มีฟอร์มซ้ำต่อท้าย ต้นฉบับแสดง 5 บรรทัดและกดอ่านทั้งหมดได้ ประวัติพับไว้ และปุ่มติดขอบล่างกำหนดสถานะแทน Dropdown: บันทึกไว้ก่อนเป็นรอยืนยันข้อมูล ส่วนยืนยันข้อมูลเพื่อสรุปเป็นพร้อมสรุปเมื่อข้อมูลจำเป็นครบ พร้อมแจ้งจุดที่ขาด ข้อความต้นฉบับเก็บแยกจากผลการดำเนินงานและไม่ถูกเขียนทับเมื่อแก้รายงาน ชื่อรายการเริ่มต้นมาจากบรรทัดแรกหรือชื่อไฟล์เพื่อค้นหาเท่านั้น ไม่มีการเดาวันที่ ผู้ปฏิบัติงาน หรือจำนวนจากรูป รายการรอตรวจไม่รวมในยอดพร้อมสรุป

อ่าน PDF ที่มีข้อความ, Excel .xlsx และ OCR เอกสารสแกนในเครื่องได้แล้ว โดยเสนอข้อมูลจากกติกาและหลักฐานข้อความ ไม่ใช้ AI ผู้มีสิทธิ์ต้องตรวจข้อมูลจากต้นฉบับก่อนยืนยัน ฝ่ายที่ระบบใช้รับเรื่องเริ่มต้นมาจากบัญชีผู้ส่ง จึงต้องตรวจเจ้าของรายงานย้อนหลังอีกครั้ง การย้ายฝ่ายยังอยู่ภายใต้สิทธิ์หัวหน้าที่รับผิดชอบ ไม่ได้เปิดให้พนักงานย้ายรายงานข้ามฝ่ายโดยเสรี

รูปและไฟล์ที่ส่งพร้อมข้อความจะแนบกับรายงานอัตโนมัติ หากเพิ่มภายหลัง ใช้ปุ่มเพิ่มไฟล์แนบ เลือกอัปโหลดจากเครื่องหรือเลือกจากคลังไฟล์ที่มีสิทธิ์ รายงานที่บันทึกแล้วจะเก็บไฟล์แนบทันทีโดยไม่ต้องยืนยันข้อมูลซ้ำ การเลือกไฟล์ฝากเก็บจะสร้างสำเนาหลักฐานและคงต้นฉบับในคลังไว้ ตัวเลือกฝากไฟล์ระบุว่าเก็บไว้ค้นหาเท่านั้น — ไม่รวมในสรุปผลงาน

เมื่อเลือกเก็บไว้ค้นหาเท่านั้น ช่องข้อความยังใช้งานได้ทั้งแบบข้อความพร้อมไฟล์และข้อความอย่างเดียว ข้อความค้นหาได้ในคลังและเปิดอ่านพร้อมไฟล์ โดยไม่สร้างรายงานหรือเพิ่มยอดกิจกรรม

## อ่านไฟล์ในเครื่อง

ติดตั้งภาษา OCR ไทยและอังกฤษครั้งแรกด้วย `npm run ocr:setup` (ต้องใช้อินเทอร์เน็ตเฉพาะตอนดาวน์โหลดโมเดล) หลังจากนั้นอ่านเอกสารในเครื่องได้ ไม่ต้องมี API key ดูสถานะที่ **ดูแลระบบ → หน่วยงานและหมวดข้อมูล**

PDF ที่มีข้อความและ Excel `.xlsx` อ่านได้ทันทีหลัง `npm ci`; Excel เก่า `.xls` ฝากเก็บได้ แต่ต้องแปลงเป็น `.xlsx` ก่อนอ่าน รูปถ่ายกิจกรรมแนบเป็นหลักฐานตามเดิม หากเป็นภาพเอกสารให้เลือกอ่านตัวหนังสือในรูปด้วย ข้อมูลที่พบจะเติมเฉพาะช่องว่าง รอเจ้าหน้าที่ตรวจยืนยันจึงรวมยอด

รายละเอียดขอบเขตและการแก้ปัญหา: [คู่มือการอ่านไฟล์ในเครื่อง](docs/LOCAL-READING.md)

## LINE และ AI

กำหนด Messaging API channel ของหน่วยงานใน `.env`: `LINE_CHANNEL_SECRET`, `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_REPORT_GROUP_ID`, `LINE_NEWS_GROUP_ID`

- Webhook: `POST https://<โดเมน>/api/line/webhook` ตรวจ HMAC จาก raw body รับเฉพาะกลุ่มที่กำหนด และกัน event ซ้ำ
- localhost ยังรับ webhook จาก LINE ไม่ได้ ต้องมี HTTPS ที่ LINE เรียกถึง
- ผูก LINE User ID กับบัญชีผู้รายงาน หากยังไม่ผูก จะเก็บข้อความรอและยังนำไปสร้างงานไม่ได้
- ผู้มีสิทธิ์เลือกข้อความรวมเป็นหนึ่งงานได้ ไฟล์/รูปมีปุ่มดาวน์โหลดต้นฉบับจาก LINE แล้วเก็บจริงลงดิสก์ ควรดาวน์โหลดโดยเร็วตามข้อจำกัดอายุไฟล์ของ LINE
- PR ต้องเผยแพร่บนฟีดก่อน แล้วกดส่ง LINE แยกอีกครั้ง ส่งข้อความข่าวจริงด้วย Push API และ retry key เดิมเพื่อกันคำขอซ้ำ แสดง “LINE รับคำขอแล้ว” ไม่ใช่การยืนยันว่าผู้รับอ่านแล้ว
- **ยังไม่ได้เชื่อมบริการ AI** ตามที่เลือกใช้การอ่านไฟล์ในเครื่องก่อน อ่าน PDF/Excel/OCR ได้โดยไม่ส่งเอกสารออกไปบริการภายนอก ข้อเสนออาจอ่านไม่ครบ ต้องตรวจและยืนยันเอง ไม่มี AI เขียนข่าวหรือรายงานแทน

อ้างอิง [LINE signature](https://developers.line.biz/en/docs/messaging-api/verify-webhook-signature/) และ [LINE retry keys](https://developers.line.biz/en/docs/messaging-api/retrying-api-request/)

## สรุปผลงานและโครงการ (ปรับตามข้อเสนอแนะ 17 ต.ค. 2569)

เพิ่มเมนู **สรุปผลงาน**: รายเดือน ไตรมาสงบประมาณ ปีงบประมาณ (ต.ค.–ก.ย.) และกำหนดเอง พร้อมเทียบรอบก่อน กรองฝ่าย/งาน/ประเภท เปิดรายงานต้นทาง ดาวน์โหลด CSV และพิมพ์/บันทึก PDF โดยรวมเฉพาะรายงานยืนยัน และแยกหน่วยนับ

เพิ่มเมนู **โครงการและงานมอบหมาย**: หัวหน้าสร้างและมอบหมายเจ้าหน้าที่ในฝ่าย เจ้าหน้าที่ส่งรายงานที่ยืนยันแล้วให้หัวหน้าตรวจรับหรือส่งกลับ ปิดโครงการเมื่อทุกงานผ่าน มีประวัติและสถานะเลยกำหนดในเว็บ ยังไม่ส่งข้อความเตือนอัตโนมัติ

API สองส่วนใหม่นี้จำกัดข้อมูลตามบทบาท: เจ้าหน้าที่เห็นข้อมูลตนนำเข้า/งานที่ได้รับมอบหมาย หัวหน้าเห็นตาม scopes ผู้บริหารเห็นทั้งสำนัก ผู้ดูแลระบบอย่างเดียวไม่มีสิทธิ์ส่วนนี้ สิทธิ์อ่านข้อมูลภายในเดิมในคลัง/แดชบอร์ดยังคงเดิม รายงานที่ส่งแทนผู้อื่นไม่ถูกอ้างว่าเป็นผลงานส่วนตัว

ดู [ขอบเขตที่ประยุกต์ วิธีลอง และส่วนที่ยังไม่เชื่อม](docs/PROTOTYPE-ADAPTATION.md) ไม่คัดลอกตัวเลขสาธิตหรือแสดง AI/การส่ง LINE ที่ยังไม่มีบริการเป็นการทำงานจริง

## ข้อมูลและการสำรอง

อัปเดต 18 ต.ค. 2569: แอดมินตั้ง **แม่แบบข้อมูลและรายงานสรุป** ในแท็บหน่วยงานและหมวดข้อมูล → รูปแบบรายงานได้แล้ว มีหน้า **สร้างร่างรายงานสรุปผล** สำหรับเลือกรายงาน ตรวจข้อมูลขาด/อาจซ้ำ แก้ข้อความ เลือกรูป และยืนยันฉบับก่อนส่งออก Word หรือพิมพ์ PDF ฉบับยืนยันเก็บสำเนาข้อมูล แม่แบบ และรูป ณ เวลาจัดทำ ไม่เปลี่ยนตามต้นทางภายหลัง ตัวเลขคำนวณจากฐานข้อมูล ส่วนข้อความตั้งต้นยังใช้กติกา ไม่ใช่ AI

แม่แบบประชุม/อบรมและเก็บขยะเริ่มต้นปิดไว้ ให้แอดมินตรวจแล้วเปิดใช้ ดู [วิธีลอง ขอบเขตที่ทำแล้ว และสิ่งที่ยังต้องพัฒนา](docs/SUMMARY-DRAFTS.md)

- `data/rm.sqlite`: ผู้ใช้ session หน่วยงาน งาน metadata ไฟล์ ข่าว audit
- `data/uploads/`: ไฟล์จริง ชื่อภายในสุ่ม ไม่เปิดเป็น public directory
- SQLite ใช้ WAL, foreign keys และ migrations มีเวอร์ชัน
- `.env`, `.first-admin.txt`, `data/`, `backups/` ไม่ขึ้น GitHub

```sh
npm run backup
```

สร้าง `backups/<timestamp>/rm.sqlite` และ `uploads` ด้วย SQLite backup API ควรงดการเขียนข้อมูลระหว่างสำรองให้ไฟล์และฐานข้อมูลตรงกัน กู้คืนโดยหยุดเซิร์ฟเวอร์ เก็บชุดปัจจุบันไว้ แล้วนำฐานข้อมูลและ uploads จากชุดเดียวกันกลับไป `DATA_DIR` ก่อนเริ่มใหม่

## การทดสอบ

```sh
npm test
npm run build
npm run test:browser
npm run test:workflows
npm run test:drafts
npm run test:usability
```

Tests ใช้ฐานข้อมูลชั่วคราวแยกจากข้อมูลจริง ตรวจสิทธิ์ session CSRF ไฟล์ ยอดสรุป ข่าว audit และ LINE HMAC Browser tests ใช้ Chrome บน macOS หรือกำหนด `CHROME_PATH`; ระบบอื่นติดตั้งด้วย `npx playwright install chromium` ทดสอบหน้าจอ 1440, 390 และ 768 px ภาพอยู่ใน `test-results/` และไม่ขึ้น GitHub

## ข้อมูลสาธิตสำหรับลองทุกระบบ

ใส่ข้อมูลตัวอย่างด้วยคำสั่ง `npm run demo:seed` เมื่อผู้ดูแลต้องการนำเสนอระบบเท่านั้น ไม่ทำงานอัตโนมัติเมื่อเปิดเว็บ และปฏิเสธการรันเมื่อ `NODE_ENV=production` คำสั่งสำรองฐานข้อมูล/ไฟล์ก่อนเพิ่ม เก็บข้อมูลเดิม สร้างข้อมูลชุดเดียวครั้งเดียว และไม่เขียนทับเมื่อเรียกซ้ำ

ชุดตัวอย่างมีบัญชีครบ 5 บทบาท (พนักงาน 9 ฝ่าย/กลุ่มงาน + หัวหน้า + ผู้บริหาร + PR + แอดมิน) รายงาน 18 รายการ, ข่าวฟีดภายใน 4 ข่าว, ข่าวร่าง 2 ข่าว, ไฟล์จริง 9 ไฟล์ และข้อความ LINE จำลอง 5 รายการ โดยไม่มีการติดต่อหรือส่ง LINE จริง ข่าวและรายงานระบุ `[สาธิต]` ชัดเจน และหน้าเว็บเตือนว่าตัวเลขสรุปรวมข้อมูลสาธิตด้วย

รหัสผ่านสุ่มเก็บเฉพาะเครื่องใน `DATA_DIR/demo/accounts.md` (สิทธิ์ไฟล์ 0600, อยู่ใน data ที่ไม่ขึ้น GitHub) ไม่ใส่รหัสผ่านในซอร์สหรือ log ดูลำดับการลองที่ [คู่มือสาธิต](docs/DEMO.md)
